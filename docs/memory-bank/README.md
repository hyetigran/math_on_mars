## Authority and maintenance

The latest owner instructions take precedence. [GAME_PLAN.md](../GAME_PLAN.md) is the product source of truth; [ARCHITECTURE.md](../ARCHITECTURE.md) contains technical contracts; [CONTEXT.md](../../CONTEXT.md) is the domain glossary. This bank summarizes them and records handoff state.

After a material decision or implementation change, update the affected memory file and the authoritative plan when needed. Keep active context focused on the next work, and progress factual about what exists and what was verified. Distinguish confirmed requirements, prototype defaults, and implemented behavior. Replace obsolete notes rather than accumulating contradictory history. Record actual checks and limitations; never promote historical calculations into proof that the game works.
